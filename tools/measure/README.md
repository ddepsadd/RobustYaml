# Замеры индексов

Прогон настоящих индексаторов плагина по чекауту Space Station 14. Нужен после любой правки
`RobustComponentNameIndex`, `RobustDataFieldIndex`, `RobustPrototypeIdIndex`,
`RobustYamlReferenceIndex`, `RobustLocaleIndex` и `RobustMigrations`.

```bash
./gradlew :compileKotlin
tools/measure/run.sh ~/RiderProjects/ss14-wega
```

Третьим аргументом можно назвать одну проверку: `MeasureHoles`, `MeasureReferences`,
`MeasureMigrations`, `MeasureRequired`, `MeasureScalars`, `MeasureLocalization`.

## Что проверяется

| Замер | Вопрос | Признак поломки |
|---|---|---|
| `MeasureHoles` | эвристика имён компонентов ещё эквивалентна чтению `[RegisterComponent]`? | непустой `MISSING`, выход с кодом 1 |
| `MeasureReferences` | что подсветит дерево: ошибки и предупреждения по всему контенту | рост числа файлов против ожидаемого |
| `MeasureMigrations` | `migration.yml` разбирается целиком, а quick fix не предложит несуществующий id | расхождение строк и записей либо ненулевые `rename targets that do not exist` |
| `MeasureRequired` | инспекция обязательных датафилдов на смерженном наследовании | ненулевые `missing required values` |
| `MeasureScalars` | правила чтения значений (`bool`, числа, `TimeSpan`, `Color`, векторы, `Angle`) | рост `rejected` сверх 17 известных |
| `MeasureLocalization` | индекс `.ftl`, разбор тела для ховера, ссылки `LocId`, quick fix по опечаткам | падение числа id, рост `missing` сверх 1 либо `no readable body` сверх 3, падение `suggested back` |
| `MeasureTags` | предпосылка проверки `!type:`: тип тега объявлен в чекауте и не абстрактен | рост `not declared` сверх 1 либо ненулевые `declared abstract` |
| `MeasureUsages` | цена Alt+F7: сколько файлов придётся открыть и резолвить на одно значение | рост числа файлов у популярных значений, падение доли значений из одного файла |
| `MeasureDeadLocale` | выполнимость проверки неиспользуемых сообщений: сколько ключей `.ftl` не найдены ни одним из шести источников | рост `unused` сверх 3999 — значит потерян ещё один способ ссылаться на ключ |

`MeasureScalars` зовёт `RobustValidation.accepts` — то есть меряет саму отгружаемую валидацию,
а не её пересказ. Имя ключа проверяется, только когда все `[DataField]` с этим именем во всём
чекауте объявляют один и тот же тип: плагин узнаёт тип у бэкенда по владельцу, замер так не умеет,
а неоднозначное имя (`state` — это и `bool`, и `string`, и дюжина enum) дало бы шум, ничего не
говорящий о правилах. Поля с `customTypeSerializer` исключаются по тому же признаку, по которому
их пропускает плагин. Известные 17 отвержений — совпадения имён: `on`/`broken` и `delta` там ключи
словарей `spriteStateMap:` и `alertVisuals:`, `bar` — цвет в палитре, `step` — мёртвый ключ
`PointingArrow`; у плагина тип приходит по владельцу, и на них он молчит.

`MeasureTags` проверяет не сам ответ бэкенда (наследников офлайн не посчитать), а предпосылку
проверки тегов: тип, названный в `!type:`, объявлен где-то в чекауте и инстанцируется. Шесть имён
из `ReflectionManager.TryLooseGetType` (`Byte`, `Bool`, `Double`, `SByte`, `Single`, `String`)
считаются отдельно: класса с такими именами нет — это примитивы, и без отдельной ветки они дали бы
154 ложных ошибки. Комментарии YAML вырезаются до поиска: закомментированный
`#      operator: !type:StashActiveHandOperator` в `NPCs/generic.yml` ссылкой не является — PSI там
вообще не строит ключа, — а замер читал файл как обычный текст и объявлял находку на пустом месте.
Ожидаемые значения на ss14-wega: 12453 тегированных значения в 1299 файлах, 787 типов, 154 алиаса,
1 мёртвый тег (`WashCreamPieReaction` в `_Wega/.../Xenobiology/base.yml`), 0 абстрактных.

`MeasureHoles` — тот самый сторож, из-за которого замена эвристики на ReSharper-бэкенд отложена:
пока `MISSING` равен нулю, regex-индекс эквивалентен чтению атрибута, и менять его не на что.
Ожидаемые значения на ss14-wega: 0 потерянных имён, 9 лишних (тестовые классы движка и пример
в `AccessAttribute.cs`), из них 0 используются в прототипах.

## Почему замер, а не модель на python

Модель эвристики на python однажды приписала `- type: DiseaseProtection # комментарий` предыдущему
компоненту и насчитала 536 «мёртвых» ключей вместо 45. Поэтому companion-функции индексов зовутся
рефлексией по `build/classes/kotlin/main`.

Тот же класс ошибок ловит `Cs.java`: разбор атрибутов нельзя писать поиском назад до `}` или `;` —
и то и другое встречается внутри `[Access(new[] { typeof(X) })]` и внутри комментариев
(`// ... need Solution data;`). Комментарии и литералы сначала забиваются пробелами с сохранением
смещений, и только потом собирается список атрибутов с балансировкой скобок. Имя из
`[ComponentProtoName("...")]` при этом читается из исходного текста — в забланкированном литерал уже
превращён в пробелы.

## Устройство запуска

`run.sh` собирает classpath сам: распакованный дистрибутив Rider из `~/.gradle/caches`,
`kotlin-stdlib` оттуда же и классы плагина. `ID.create` в статической инициализации индекса лезет
в `PathManager.getHomeDir`, поэтому скрипт создаёт временный каталог с пустым `product-info.json`
и передаёт его в `-Didea.home.path`.
